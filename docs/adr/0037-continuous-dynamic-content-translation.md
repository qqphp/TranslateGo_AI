# ADR-0037：整页翻译后持续监听并追加翻译动态内容

- 状态：已接受
- 日期：2026-07-28

## 背景

新闻流、无限滚动页面和 SPA 经常在首次整页翻译完成后继续插入或更新正文。只扫描一次 DOM 会让后续内容保持原语言，用户必须重复手动触发整页翻译，并可能再次翻译已经处理过的内容。

## 决策

用户主动启动整页翻译后，content script 使用 `MutationObserver` 持续监听主文档中的新增节点、文本变化，以及由 `class`、`style` 或 `hidden` 引起的可见性变化。

符合现有可见文本范围的新内容经过 400ms 防抖和文本节点去重后，以独立的追加任务发送给 service worker。追加任务复用现有的活动档案、批处理、固定并发、自动重试、任务 ID 和节点 ID 协议，并且只在前一个页面任务完成后启动。

插件替换的译文和带插件标识的双语译文必须被监听器忽略。替换模式下，如果网页自身再次更新一个已翻译文本节点，恢复原文时应恢复为网页最新提供的原文。

首次及每次追加翻译完成后，页面面板显示本次持续翻译会话累计成功翻译的文本段数，并明确提示仍在监听新内容。用户取消、恢复原文、切换档案、刷新或关闭标签页时停止监听。

## 影响

- 无限滚动和 SPA 页面可以在一次主动触发后持续获得翻译。
- 动态追加会继续调用用户配置的 API；完成提示必须持续披露监听状态，取消和恢复操作必须停止后续调用。
- 监听和累计状态只存在于当前页面内存，不持久化，也不跨页面导航恢复。
- 每个追加任务仍遵循单次任务请求预算；多个追加任务可能在长时间阅读中产生额外 API 成本。
