# 大模型网页翻译浏览器插件 PRD

- 状态：MVP 需求规格
- 版本：0.1
- 日期：2026-07-26
- 目标平台：Chrome 桌面版、Microsoft Edge 桌面版
- 技术方向：Manifest V3、TypeScript、Vite、原生 DOM、Chromium Extension API

## Problem Statement

用户在阅读外文新闻、技术文档、论坛和其他网页时，需要在网页阅读体验与翻译质量之间反复取舍：传统整页翻译可能破坏页面布局、交互和上下文；独立翻译工具又需要复制粘贴，打断阅读流程。

同时，不同用户拥有不同的大模型 API 供应商、模型和网关配置。用户希望直接使用自己配置的大模型服务，而不是依赖一个统一后端、共享账号或广告支持的翻译服务。

当前产品需要解决的问题是：在不建设后端、不持久化网页内容的前提下，让用户能够通过浏览器插件主动翻译整页网页或选中文本，并保持简洁、快速、低干扰、可恢复的阅读体验。

## Solution

构建一个面向 Chrome 和 Edge 桌面版的 Manifest V3 浏览器插件：

- 用户在插件中维护多个命名的模型配置档案。
- 每个配置档案包含 OpenAI 兼容 API 的 Base URL、API Key、模型名、源语言、目标语言和翻译模式。
- 用户通过网页右键菜单主动触发整页翻译。
- 插件只处理当前页面主文档中的可见文本节点，跳过 iframe、Shadow DOM、代码块、表单、脚本和样式。
- 扩展 service worker 负责读取本地配置、发起非流式模型请求、管理并发和重试；content script 负责 DOM 提取、页面回写和页面内交互。
- 替换模式临时覆盖原文，并支持恢复原文；保留原文模式在原文后插入带插件标识的译文元素。
- 用户选中文本后看到悬浮翻译按钮，点击后在选区附近显示翻译气泡。
- 插件不持久化网页原文或译文，不做遥测，不记录完整请求正文。
- 界面支持简体中文、繁体中文、英文和日文，并根据浏览器语言选择界面语言，未知语言回退英文。

## User Stories

1. As a 网页阅读用户, I want to 通过右键菜单触发整页翻译, so that 我不需要复制网页内容到其他翻译工具。
2. As a 网页阅读用户, I want to 手动选择源语言和目标语言, so that 我可以控制翻译方向而不依赖自动检测。
3. As a 网页阅读用户, I want to 在整页翻译前看到待处理文本节点或请求规模提示, so that 我能预估可能产生的 API 成本。
4. As a 网页阅读用户, I want to 取消正在进行的整页翻译, so that 我可以控制等待时间和 API 消耗。
5. As a 网页阅读用户, I want to 按页面顺序看到分批翻译结果, so that 我不必等待整页全部完成才能开始阅读。
6. As a 网页阅读用户, I want to 看到翻译任务的运行中、完成、部分失败、已取消和失败状态, so that 我能理解当前页面的翻译进度。
7. As a 网页阅读用户, I want to 在替换模式下用译文临时覆盖原文, so that 我可以获得更接近原网页的阅读布局。
8. As a 网页阅读用户, I want to 在替换模式下恢复原文, so that 翻译结果不会永久破坏当前页面内容。
9. As a 网页阅读用户, I want to 切换目标语言前自动恢复原文, so that 新语言不会基于旧译文再次翻译。
10. As a 网页阅读用户, I want to 在保留原文模式下看到紧跟原文的译文, so that 我可以对照原文阅读。
11. As a 网页阅读用户, I want to 插件插入的译文元素不被再次识别为原文, so that 重复翻译不会不断增加页面内容。
12. As a 网页阅读用户, I want to 原页面的链接、按钮、表单和脚本行为保持可用, so that 翻译不会破坏网页交互。
13. As a 网页阅读用户, I want to 代码块和样式内容不被翻译, so that 技术资料和页面结构不会被破坏。
14. As a 网页阅读用户, I want to 页面刷新后恢复原文, so that 翻译只影响当前阅读会话。
15. As a 网页阅读用户, I want to 某个节点失败后其他节点继续翻译, so that 一处网络或模型错误不会导致整页结果全部丢失。
16. As a 网页阅读用户, I want to 失败节点自动重试 3 次, so that 短暂网络问题不会立即造成失败。
17. As a 网页阅读用户, I want to 查看失败节点汇总并单独重试, so that 我可以补齐部分失败的翻译。
18. As a 网页阅读用户, I want to 选中文本后看到悬浮翻译按钮, so that 我可以只翻译感兴趣的内容。
19. As a 网页阅读用户, I want to 点击悬浮按钮后在选区附近看到翻译气泡, so that 翻译结果不会打断当前阅读。
20. As a 网页阅读用户, I want to 选中文本翻译默认需要显式点击, so that 插件不会在我只是选择或复制文字时意外调用 API。
21. As a 模型 API 用户, I want to 配置自己的 Base URL、API Key 和模型名, so that 我可以使用自己的供应商、网关或自部署服务。
22. As a 模型 API 用户, I want to 保存多个命名配置档案, so that 我可以在不同模型和服务之间快速切换。
23. As a 模型 API 用户, I want to 测试配置档案的连接, so that 我可以在翻译前发现地址、密钥或模型配置错误。
24. As a 模型 API 用户, I want to API Key 只保存在本机, so that 我的密钥不会通过浏览器同步到其他设备。
25. As a 模型 API 用户, I want to API 请求不经过产品后端, so that 我可以直接控制网页内容发送给哪个服务商。
26. As a 模型 API 用户, I want to 看到 API 错误但不暴露完整 API Key, so that 错误诊断不会扩大密钥泄露风险。
27. As a 模型 API 用户, I want to 自定义 OpenAI 兼容 Base URL, so that 我不被限制在插件内置的供应商清单中。
28. As a 模型 API 用户, I want to HTTPS 地址校验, so that API Key 不会被默认通过不安全 HTTP 发送。
29. As a 隐私敏感用户, I want to 插件不持久化网页原文和译文, so that 关闭任务后本地不会留下网页内容。
30. As a 隐私敏感用户, I want to 插件不上传遥测和使用统计, so that 我的使用行为不会被产品收集。
31. As a 隐私敏感用户, I want to 看到网页数据流向说明, so that 我知道内容只会发送到自己配置的 API。
32. As a 国际化用户, I want to 使用简体中文、繁体中文、英文或日文界面, so that 我可以用熟悉的语言配置插件。
33. As a 国际化用户, I want to 未支持的浏览器语言回退英文, so that 界面始终可用。
34. As a Chrome 用户, I want to 在普通网页上使用整页和选中文本翻译, so that 插件能覆盖我的主要阅读场景。
35. As a Chrome 用户, I want to 在受限页面看到明确的不支持提示, so that 我不会误以为插件发生故障。
36. As a Edge 用户, I want to 使用与 Chrome 相同的核心翻译能力, so that Chromium 浏览器切换不会改变主要体验。
37. As a 插件用户, I want to 工具栏图标打开设置而不直接触发翻译, so that 点击图标不会意外消耗 API 配额。
38. As a 插件用户, I want to 设置页清晰区分当前配置档案、语言方向和翻译模式, so that 我能在翻译前确认实际使用的参数。
39. As a 插件用户, I want to 页面刷新、关闭标签页或后台任务失效时任务被取消, so that 插件不会在我看不到页面时继续消耗 API。
40. As a 发布者, I want to 插件从 MVP 起满足 Chrome Web Store 和 Edge Add-ons 的隐私、权限和素材要求, so that 产品可以按计划发布。

## Implementation Decisions

- 使用 Manifest V3，支持 Chrome 桌面版和 Edge 桌面版，优先使用 Chromium 共通 Extension API。
- 使用 TypeScript、Vite 和原生 DOM，不引入 React 等 UI 框架。
- 系统由 options/settings UI、service worker、content script 和消息协议组成。
- service worker 统一负责读取配置、发起模型请求、解析普通 JSON 响应、管理固定低并发、自动重试和任务协调。
- content script 负责主文档可见文本节点提取、节点 ID 管理、译文回写、替换模式、保留原文模式、恢复原文以及选中文本交互。
- API Key 不下发给网页 content script，只在 service worker 中使用。
- 第一版只实现 OpenAI 兼容 Chat Completions 协议，采用普通 JSON 响应；选中文本输出纯译文，整页批量输出带节点 ID 的 JSON 译文。
- 每个配置档案至少保存名称、Base URL、API Key、模型名、源语言、目标语言和翻译模式。
- Base URL 必须是 HTTPS；`localhost` 可作为开发环境例外。其他 HTTP 地址不允许保存或测试。
- 配置全部使用 `chrome.storage.local`，不使用 `chrome.storage.sync`，不支持配置导入导出。
- 整页翻译通过网页右键菜单触发；工具栏图标只打开设置。
- 只处理当前页面主文档中的可见文本节点；排除 iframe、Shadow DOM、代码块、表单、脚本、样式和其他非用户阅读内容。
- 第一版不根据文本内容过滤节点，即不主动过滤纯数字、URL、邮箱或短文本；该策略可能增加 API 请求量。
- 采用带节点 ID 的翻译：每个节点单独请求，当前速度测试并发上限为 5。请求并行执行，但按页面顺序回写，并通过任务 ID 和节点 ID 将结果回写到对应节点。
- 每个节点最多自动重试 3 次；重试失败后继续后续节点，最终任务标记为部分失败并提供失败项重试能力。
- 翻译任务严格绑定当前标签页；页面刷新、标签页关闭或后台通信失效时取消，不支持断点续译。
- 替换模式只临时覆盖当前 DOM，页面刷新或用户恢复操作后恢复原始文本。切换目标语言前必须先恢复原文。
- 保留原文模式在原文后插入带插件标识的译文元素，避免译文元素被再次扫描。
- 选中文本后显示悬浮翻译按钮；只有用户点击按钮后才发起 API 请求，并在选区附近显示翻译气泡。
- 设置界面支持简体中文、繁体中文、英文和日文，可在设置页手动选择或跟随浏览器语言；未支持语言回退英文。界面语言不自动决定翻译源语言或目标语言。
- 安装时申请 `<all_urls>`，隐私说明必须解释：网页内容只在用户主动翻译时读取，并只发送到用户配置的 API。Chrome 受限页面和 Edge 对应受限页面明确不支持。
- 插件不持久化网页原文、译文或完整 API 请求正文，不做遥测，不上传使用统计；任务状态仅存在于当前运行内存。
- 每个节点单独请求；单次整页任务最多发起 200 次 API 调用（自动重试也计入），无重试时最多处理前 200 个节点。整页翻译使用当前档案配置的替换原文或保留原文模式。开始翻译前展示待处理节点、请求规模和未处理数量，并始终提供取消操作。
- 发布前必须具备整页右键触发、分批翻译、两种翻译模式、恢复原文、失败重试、选中文本气泡、多配置档案和四语言 UI。
- 需要准备隐私政策、权限用途说明、数据流向说明、受限页面说明、API Key 本地存储说明，以及 Chrome Web Store 和 Edge Add-ons 所需素材。

## Testing Decisions

- 测试只验证用户可观察的外部行为，不绑定具体内部函数、文件组织或实现细节。
- 当前仓库没有已有代码、测试框架或测试先例，因此不存在可复用的 prior art。
- 建议的最高测试 seam 是浏览器端到端测试：真实加载 Manifest V3 扩展、使用测试网页、连接 fake OpenAI-compatible Chat Completions 服务，并验证从触发到 DOM 回写的完整链路。
- 该 seam 目前按用户选择暂不最终确认，测试实现应在正式开发前重新确认。
- 少量单元测试应补充高风险边界：普通 JSON 响应解析、模型响应错误处理、Base URL 校验、重试次数、任务状态转换、可见文本节点筛选和原文/译文恢复。
- 真实网页测试集作为发布门槛，至少覆盖新闻页面、技术文档、论坛、SPA 和表单密集页面。
- 真实网页验收应检查：普通页面加载不被破坏、原有链接和表单交互仍可用、代码块不被翻译、替换模式可恢复、保留原文模式不造成明显布局破坏、部分失败能继续、取消能停止后续请求、受限页面提示正确。
- API 测试应覆盖正常 JSON 响应、空响应、无效 JSON、连接中断、非标准错误和重试。
- 配置测试应覆盖多配置档案的新增、编辑、删除、切换、连接测试、敏感字段展示和本地持久化边界。
- 国际化测试应覆盖四种支持语言、浏览器语言匹配和未知语言回退英文。
- Chrome 和 Edge 至少都要完成核心手工验收；如果最终选择双浏览器 E2E，则应对两者分别运行同一测试集。

## Out of Scope

- 不建设统一后端、用户账号、订阅、计费或平台托管 API Key。
- 不实现原生 Anthropic、Google、OpenAI Responses API 或其他非 OpenAI 兼容协议适配器。
- 不维护内置主流模型清单；模型能力由用户提供的兼容 Base URL 和模型名决定。
- 不支持移动端浏览器。
- 不支持 iframe、跨域 iframe、Shadow DOM 或其他页面文档的翻译。
- 不保证动态加载内容自动翻译。
- 不翻译代码块、表单控件、脚本、样式和受限页面。
- 不实现源语言自动检测或目标语言自动推断。
- 不实现翻译缓存、历史记录、云端同步、配置导入导出或断点续译。
- 不开放自定义系统提示词、翻译风格和术语表。
- 不支持自动翻译页面或在用户未显式操作时自动调用 API。
- 不设置智能并发调度；当前速度测试使用每节点一个请求和固定 5 并发。
- 不提供遥测、匿名使用统计或网页内容分析。
- 不承诺任意 OpenAI 兼容服务的全部扩展字段，只依赖约定的基础 Chat Completions JSON 响应行为。

## Further Notes

- “支持绝大部分主流大模型”在本 PRD 中被具体化为支持 OpenAI 兼容 API，而不是逐个内置供应商适配器。
- 固定请求预算仍会带来成本风险。产品必须在用户主动触发翻译前展示规模提示，不能将请求规模隐藏在自动行为中。
- `<all_urls>` 是发布审核和用户信任的关键风险，隐私政策、商店描述和插件内提示必须保持一致。
- service worker 的生命周期、消息丢失、任务取消和标签页绑定是实现中的高风险区域，应优先建立测试 seam。
- 替换模式必须始终以原始文本作为翻译基准，不能把译文再次作为后续翻译输入。
- 当前 ADR 和术语表是本 PRD 的领域约束来源；后续实现若要改变这些决策，应新增或更新 ADR，而不是在代码中隐式改变行为。
